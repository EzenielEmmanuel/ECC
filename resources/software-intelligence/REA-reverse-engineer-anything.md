# REA — Reverse Engineer Anything: ORIS / SOCRF resource candidate

**Source:** https://rea.tools/  
**Upstream repository (verify before installation):** https://github.com/morluto/rea  
**Category:** Software behavior analysis / outcome-driven reconstruction  
**Status:** Resource candidate; not installed, benchmarked, or integrated.

## Vision
Evaluate REA as an optional analysis tool for AI Workshop Studio, ORIS Workshop, SOCRF and specialized executive / production / QA agents. The goal is to observe *publicly accessible outcomes* of exemplary app builders (e.g. Lovable), derive product requirements and interaction patterns, and create an independently engineered app factory with potentially stronger results — **without accessing proprietary source code, bypassing access controls, or copying protected assets**.

## Proposed agent workflow
1. Observe authorized user-visible outputs and workflows: prompts, UI screenshots, preview behavior, editing, debugging, deployment.
2. Produce behavioral specifications, acceptance criteria and original UX patterns.
3. Benchmark ORIS outputs against measurable tasks: prompt-to-app quality, functionality, reliability, iteration speed, accessibility, responsiveness and cost.
4. Ask REA to analyze only software we own or are authorized to inspect; for proprietary hosted tools, use permitted black-box observation and independent implementation instead.
5. Assign E-Agents for orchestration, implementation, testing, security review and continuous improvement, each with approval gates.
6. Verify REA's actual capabilities, license, prerequisites, OpenCode compatibility, compute needs and operational costs through a small reproducible test.
7. Keep generated code original, retain provenance, and do not copy trademarks, proprietary assets or confidential information.

## Priority
High-priority research candidate for the ORIS Resource Synthesis Engine. No automatic installation, merge, training, or execution is authorized by this note.
